# Журнал проблем и трудностей (problem log)

Журнал фиксирует трудности, возникшие при разработке frontend, способы их решения и оставшиеся риски.

---

## [2024 — Этап 1] Node.js не установлен в системе

- **Проблема**: `node`, `npm`, `npx`, `winget`, `scoop`, `choco` отсутствуют в PATH — невозможно инициализировать Vite-проект стандартным способом.
- **Решение**: скачал портативную сборку Node.js v20.18.1 (zip с nodejs.org), распаковал в `%TEMP%\node-portable` и подключил к PATH в каждой команде терминала.
- **Остаточный риск**: PATH действует только в рамках сессии терминала; папка в `%TEMP%` может быть очищена системой. Рекомендуется системная установка Node 20 LTS. Также была выдана ошибка `EBADENGINE` (eslint-visitor-keys требует node ^20.19.0) — только предупреждение, работоспособность не нарушена.

## [Этап 1] Шаблон Vite создал проект не на том стеке

- **Проблема**: `npm create vite@latest` (create-vite@9) сгенерировал проект на React 19 + Vite 8 + oxlint, тогда как по `AGENTS/frontend developer.md` требуется React 18 + Vite 6 + ESLint. Плюс `EBADENGINE`-предупреждения из-за engine-требований шаблона.
- **Решение**: вручную привёл `package.json` к целевому стеку (react/react-dom ^18.3, vite ^6, typescript ~5.7, eslint 9 + typescript-eslint + плагины react-hooks/react-refresh), заменил `lint: oxlint` на `eslint .`, удалил `.oxlintrc.json`-подход из скриптов.
- **Остаточный риск**: нет — после переустановки зависимостей всё совместимо.

## [Этап 1] Несовместимые опции TypeScript из шаблона

- **Проблема**: шаблонные `tsconfig.app.json` и `tsconfig.node.json` использовали опции `erasableSyntaxOnly` (поддерживается только в TS 6) и `types: ["node"]` без установленного `@types/node`; после даунгрейда до TS 5.7 — ошибки компиляции (`TS5023`, `TS2688`, `TS2792` — неразрешение модулей в `vite.config.ts`).
- **Решение**: удалил `erasableSyntaxOnly` и `types: ["node"]`; в `tsconfig.node.json` выставил `module: esnext` + `moduleResolution: bundler`.

## [Этап 1] Ограничение инструмента правки при перезаписи файлов

- **Проблема**: при замене шаблонного `src/App.tsx` (счётчик Vite) на демо-страницу — правки по частям дважды оставили «хвост» старого кода (вложенные объявления `function App`, дубли `export default App`), из-за чего `tsc` и esbuild выдавали синтаксические ошибки.
- **Решение**: дочитал файл, поэтапно удалил остатки шаблонного JSX якорными правками; файл стал чистым демо-компонентом.
- **Вывод**: шаблонные файлы лучше заменять одним цельным коммитом контента сразу после создания, а не последовательными правками.

## [Этап 1] Headless-браузер недоступен — визуальная проверка не выполнена

- **Проблема**: запуск `npx vite` и browser-automation (headless Playwright) в среде завершался таймаутом (120 с) без вывода — проверить рендер демо-страницы в браузере не удалось.
- **Решение**: ограничился статическими проверками: `tsc -b`, `vite build`, `eslint .` — все прошли без ошибок.
- **Остаточный риск**: рендер демо-страницы и иконок визуально не подтверждён. Проверка перенесена на Этап 10 (визуальный QA по `design.png`).
